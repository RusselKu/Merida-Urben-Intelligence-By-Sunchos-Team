# Warehouse data dictionary

Owner: Jonathan — QA, profiling and technical documentation. Reviewed: 2026-10-04.

This document describes [01_schema.sql](../sql/01_schema.sql), [transform.py](../src/etl/transform.py), and [03_views.sql](../sql/03_views.sql). Census mappings were checked against the official INEGI 2020 dataset during the [GeoJSON refresh](../outputs/qa/demographic_refresh.json). Other source mappings describe repository code and still require source validation. Local file counts do not certify Supabase contents.

## Conventions and analytical unit

- An urban AGEB (basic geostatistical area) uses `cvegeo`: state (2 characters) + municipality (3) + locality (4) + AGEB (4). Keep it as text, preserving leading zeros and letters. Mérida expects prefix `31050` and 13 characters; the DDL allows up to 20 and does not enforce the format.
- PK = primary key; FK = foreign key; UQ = uniqueness constraint. `SERIAL` is an integer generated by a sequence.
- “Nullable / default” describes PostgreSQL behavior. Proposed QA rules are not necessarily implemented constraints.
- Geographic coordinates use longitude, latitude order and SRID 4326. Areas are calculated in EPSG:6372 and expressed in km².
- The warehouse keeps one demographic row per AGEB without a census-year dimension; a reload updates that row. Business and crime facts have internal keys but no unique source identifiers.
- Zero may represent an observation, a default or ETL imputation. It does not independently establish absence of population, businesses or crime.

## 1. `dim_geografia`

Grain: one row per urban AGEB. Source: cartography from `31a.shp`. The ETL filters state `31` and municipality `050`, without restricting locality to `0001`.

| Field | SQL type | Nullable / default | Meaning, source and quality rule |
| --- | --- | --- | --- |
| `cvegeo` | VARCHAR(20), PK | No | `CVEGEO`; territorial identifier. Validate composition, length and uniqueness. If absent, the code uses the dataframe index, which requires review. |
| `cve_ent` | VARCHAR(2) | No / `'31'` | `CVE_ENT`; state code. Expected: `31`. |
| `cve_mun` | VARCHAR(3) | No / `'050'` | `CVE_MUN`; municipality code. Expected: `050`. |
| `cve_loc` | VARCHAR(4) | No | `CVE_LOC`; locality code. Defaults to `0001` if missing. |
| `cve_ageb` | VARCHAR(4) | No | `CVE_AGEB`; alphanumeric AGEB component. Defaults to `0000` if missing. |
| `nom_asentamiento` | VARCHAR(255) | Yes | The ETL assigns `Mérida Urbana`; not an individual neighborhood name. |
| `tipo_asentamiento` | VARCHAR(50) | Yes | The ETL assigns `AGEB Urbana`. |
| `area_km2` | NUMERIC(10,4) | No | Area projected to EPSG:6372, divided by 1,000,000 and rounded to four decimals. Must be positive; no DDL `CHECK`. |
| `geom_4326` | GEOMETRY(MultiPolygon,4326) | Yes | Repaired with `buffer(0)` and reprojected to WGS84; GiST index. The REST loader in `load_full_warehouse.py` converts Polygon to MultiPolygon. The direct loader and exported SQL do not explicitly convert it. |
| `geom_6372` | GEOMETRY(MultiPolygon,6372) | Yes | Intended metric geometry; GiST index. The direct loader does not populate it. Its absence does not mean area was not calculated in a metric projection. |

## 2. `dim_tiempo`

Grain: one row per date. Intended source: business observations and incident dates. No calendar load exists in the main pipeline.

| Field | SQL type | Nullable / default | Meaning and quality rule |
| --- | --- | --- | --- |
| `tiempo_id` | SERIAL, PK | No / sequence | Internal date key. |
| `fecha` | DATE, UQ | No | Full date; unique. |
| `anio` | INT | No | Year of `fecha`. |
| `mes` | INT | No | Month of `fecha`, from 1 to 12. |
| `mes_nombre` | VARCHAR(20) | No | Month name; agree on language with the team. |
| `dia` | INT | No | Day of month, consistent with `fecha`. |
| `dia_semana` | VARCHAR(20) | No | Weekday name; the schema does not use a numeric code. |
| `es_fin_de_semana` | BOOLEAN | No | True for Saturday and Sunday. |
| `trimestre` | INT | No | Quarter, from 1 to 4, consistent with `mes`. |

Ranges and consistency are QA rules; the DDL only enforces non-null values and date uniqueness.

## 3. `dim_actividad_economica`

Implemented grain: one DENUE activity code (SCIAN class). Source: `codigo_act` and `nombre_act` in the DENUE CSV.

| Field | SQL type | Nullable / default | Meaning, source and quality rule |
| --- | --- | --- | --- |
| `scian_id` | VARCHAR(10), PK | No | Text copy of `codigo_act`; identifies a class despite the generic table name. |
| `codigo_actividad` | VARCHAR(10) | No | `codigo_act`; must match `scian_id` in the current transformation. |
| `sector_codigo` | VARCHAR(4) | No | First two characters of `codigo_act`; distinct from the complete class code. |
| `sector_nombre` | VARCHAR(255) | No | Copy of `nombre_act`: currently a class name, not necessarily a two-digit sector name. |
| `subsector_nombre` | VARCHAR(255) | Yes | Reserved field; not populated by the direct loader. |
| `categoria_macro` | VARCHAR(50) | No | Assigned by `map_scian_category()`; no category `CHECK`. |

Implemented categories: `Comercio` (trade) = 43, 46, 47; `Servicios` (services) = 51, 52, 53, 54, 55, 56, 61, 62, 71, 72, 81; `Industria` (industry) = 11, 21, 22, 23, 31, 32, 33; `Otro` (other) = remaining codes. These are project rules, not independent validation of the official catalog. The direct loader uses `ON CONFLICT DO NOTHING`, so it does not update existing descriptions.

## 4. `fact_demografia`

Grain: one census row per AGEB. Declared source: Census 2020 records with municipality `050`, `NOM_LOC = 'Total AGEB urbana'` and `MZA = 0`. The transform has no explicit state filter; the extractor selects the Yucatán dataset. The refresh utility explicitly filters state `31` and municipality `050` and rejects duplicate keys.

| Field | SQL type | Nullable / default | Meaning and source column |
| --- | --- | --- | --- |
| `fact_demografia_id` | SERIAL, PK | No / sequence | Internal identifier. |
| `cvegeo` | VARCHAR(20), FK, UQ | No | Concatenation of `ENTIDAD`, `MUN`, `LOC`, `AGEB`; references `dim_geografia.cvegeo`. Geography deletion cascades. |
| `poblacion_total` | INT | No / 0 | People; `POBTOT`. |
| `poblacion_masculina` | INT | No / 0 | People; `POBMAS`. |
| `poblacion_femenina` | INT | No / 0 | People; `POBFEM`. |
| `poblacion_0_14` | INT | No / 0 | People aged 0–14; `POB0_14`. |
| `poblacion_15_64` | INT | No / 0 | People aged 15–64; `POB15_64`. |
| `poblacion_65_mas` | INT | No / 0 | People aged 65 or older; `POB65_MAS`. |
| `poblacion_pea` | INT | No / 0 | Economically active population aged 12 or older; `PEA`. |
| `poblacion_pnea` | INT | No / 0 | Economically inactive population aged 12 or older; `PE_INAC`. |
| `total_viviendas` | INT | No / 0 | Dwellings; `VIVTOT`. Do not confuse with residents or assume all are occupied. |

The transform replaces `*`, `N/D`, `N/A`, blanks and nonnumeric values with zero and drops duplicate `cvegeo` rows, keeping the first. It does not preserve a suppression flag. The refresh utility rejects unexpected tokens and records recognized suppressed values in its [manifest](../outputs/qa/demographic_refresh.json), retaining the existing zero-imputation policy for compatibility. Counts should be nonnegative. Compare differences between population and sex/age sums with the source; a difference is not automatically a mapping error. The PEA rate is `PEA / (PEA + PE_INAC) * 100`, based on population with known activity status.

## 5. `fact_negocios`

Intended grain: one establishment per observation. The current schema cannot distinguish repeated loads or identify the DENUE snapshot date. Source: DENUE, with AGEB assigned using a `within` spatial join.

| Field | SQL type | Nullable / default | Meaning, source and quality rule |
| --- | --- | --- | --- |
| `fact_negocio_id` | SERIAL, PK | No / sequence | Internal key; not the DENUE `id`. |
| `cvegeo` | VARCHAR(20), FK | No | AGEB assigned to the point; geography reference with cascading deletion. |
| `scian_id` | VARCHAR(10), FK | No | `codigo_act`; references `dim_actividad_economica.scian_id`. |
| `tiempo_id` | INT, FK | Yes | References `dim_tiempo.tiempo_id`; not populated by the current load. |
| `nombre_establecimiento` | VARCHAR(255) | Yes | `nom_estab`; the direct loader truncates to 255 characters. |
| `estrato_personal` | VARCHAR(50) | Yes | `per_ocu`; staffing category, not an exact employee count. The direct loader truncates to 50 characters. |
| `geom_punto` | GEOMETRY(Point,4326) | Yes | `longitud`, `latitud`; GiST index. Null coordinates are dropped; only points strictly inside an AGEB are kept. Boundary and outside points are excluded. |

No source-establishment UQ or repeated-load control exists. Matching name, activity and point are duplicate candidates, not sufficient grounds to delete records.

## 7. `v_kpis_territoriales` view

Grain: one row per AGEB in `dim_geografia`. Joins demographics with business and crime aggregates. See [03_views.sql](../sql/03_views.sql) and [kpi_formulas.md](kpi_formulas.md).

| Field | Result type | Unit / implemented derivation |
| --- | --- | --- |
| `cvegeo` | VARCHAR(20) | Territorial identifier. |
| `nom_asentamiento` | VARCHAR(255) | Name from the geography dimension. |
| `area_km2` | NUMERIC(10,4) | km² from the geography dimension. |
| `poblacion_total` | INT | Residents; zero if no demographic row exists. |
| `densidad_poblacion_km2` | NUMERIC | Residents / km²; two decimals. |
| `tasa_pea_porcentaje` | NUMERIC | `100 * PEA / (PEA + PNEA)`; two decimals. |
| `poblacion_0_14` | INT | Residents; zero if demographics are missing. |
| `poblacion_15_64` | INT | Residents; zero if demographics are missing. |
| `poblacion_65_mas` | INT | Residents; zero if demographics are missing. |
| `total_negocios` | BIGINT | Establishment-row count; zero if none are associated. |
| `densidad_negocios_km2` | NUMERIC | Establishments / km²; two decimals. |
| `negocios_por_mil_hab` | NUMERIC | `1000 * businesses / population`; two decimals. |
| `densidad_comercio_km2` | NUMERIC | Rows classified as `Comercio` / km²; two decimals. |
| `densidad_servicios_km2` | NUMERIC | Rows classified as `Servicios` / km²; two decimals. |
| `actividad_economica_dominante` | VARCHAR or text | Mode of `sector_nombre`, currently a class name; no activity returns `No recorded activity`. Ties have no explicit tie-break rule. |
| `total_delitos` | BIGINT | Incident-row count; zero if none are associated. |
| `tasa_delictiva_por_mil_hab` | NUMERIC | `1000 * incidents / population`; two decimals. |
| `ratio_delito_por_negocio` | NUMERIC | Incidents / establishment; three decimals. Multiply by 100 only when reporting per hundred establishments. |
| `geom_4326` | GEOMETRY(MultiPolygon,4326) | Geometry from the geography dimension. |

`NULLIF` produces null rates for zero denominators; missing aggregates become zero through `COALESCE`. These zeros do not prove complete source loading. The view uses `security_invoker = true`; results depend on caller permissions and RLS.

## 8. API publication and remaining controls

The API reads the view and falls back to `outputs/maps/merida_agebs_demographics.geojson` when the database is unavailable or fails. That artifact also feeds the map and now contains corrected census age/inactivity values. The fallback adds zeros for missing business/crime fields and certain undefined rates; this does not establish observed absence and differs from SQL null semantics.

Before publishing, check source coverage and dates, AGEB uniqueness, referential integrity, geometry validity/SRID, age/activity variables, establishment duplicates, and warehouse/API/dashboard agreement. See [04_quality_checks.sql](../sql/04_quality_checks.sql) and [initial_data_audit.md](initial_data_audit.md). The reported 531 warehouse AGEBs versus 526 local features require a key comparison before claiming equivalent coverage.
